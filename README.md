# 传统节日视频关键帧选择实验平台

纯前端、中文界面的人工选帧实验工具。使用 React、TypeScript、Vite、HTML5 Video、Canvas、IndexedDB 和 JSZip。采用本地 CSS，无外部字体、CDN、云端接口或分析埋点。

## 启动

需要 Node.js 22.12+ 或 24 LTS：

```sh
npm install
npm run dev
```

打开终端显示的 `http://127.0.0.1:5173`。Windows 可右键用 PowerShell 运行 `start.ps1`，或执行 `powershell -ExecutionPolicy Bypass -File .\start.ps1`；该脚本优先使用本项目 `.tools` 中的便携 Node，不修改系统 PATH。安装完成后本地运行不依赖互联网。

构建：`npm run build`；预览构建：`npm run preview`。实验期间固定使用同一浏览器、配置文件、地址和端口；端口或域名改变会进入不同的 IndexedDB 存储空间。避免无痕模式。浏览器清理站点数据会删除尚未导出的本地记录。

## 发布到 GitHub Pages

项目包含自动部署工作流 `.github/workflows/pages.yml`。把代码推送到 GitHub 仓库的 `main` 或 `master` 分支后，在仓库打开 **Settings → Pages → Build and deployment**，将 **Source** 设为 **GitHub Actions**。工作流会安装依赖、按仓库名设置 Vite 子目录路径、构建并发布 `dist`。在 **Actions** 页面等待 `Build and deploy to GitHub Pages` 成功后，访问 `https://<GitHub 用户名>.github.io/<仓库名>/`。本仓库的预期地址为 `https://qingyuli0699.github.io/KeyframeExtraction/`。

GitHub Pages 发布的是公开网站。参与者的视频文件不会打包进站点，浏览器中的实验数据保存在参与者使用的设备本地。正式实验请固定站点域名、HTTPS 地址和路径，浏览器会按站点来源分别保存 IndexedDB 数据。

## 默认演示材料

首次访问且没有已保存配置或会话时，首页自动准备 `public/demo/demo.mp4`（16 秒合成测试画面），无需导入视频即可填写编号并体验阅读、练习、选帧、提交、结束页和导出。它与独立练习视频是不同资源。
已有自定义配置时不会自动覆盖，需在没有进行中会话时点击“使用内置演示材料”切换。研究者仍可通过原有文件夹、视频选择或 JSON 导入真实材料。演示会话刷新后自动关联内置视频，自定义会话仍需重新关联本地文件。
首页、选帧区及结束页明确标注演示用途，导出的 experiment_id 为 `DEMO_builtin_preview`，视频与片段编号带 `DEMO_` 前缀；演示结果不作为正式研究数据。默认材料在 `src/defaultMaterials.ts` 中配置。

## 研究者准备

也可以不编写 JSON：点击“从文件夹导入”选择视频目录（会读取子文件夹），或点击“直接选择视频”多选文件。系统按文件名自然排序，自动读取时长并关联文件。确认页可上下移动调整实验顺序，填写各片段的原视频编号和真实原视频起点，再点击“确认导入视频”。完整原视频的起点填写 0；切分片段的起点不能从文件夹推断，需按切分记录填写。目录中同名视频需先重命名，非视频文件会忽略。已有实验会话时材料不能被替换，恢复时继续使用“关联视频文件”。

1. 提前切分视频，每个文件对应一个 segment。推荐 H.264 编码 MP4，也可使用浏览器支持的 WebM。
2. 按 [配置示例](public/examples/experiment.json) 编写 JSON，设置真实原视频起点及片段时长。
3. 在准备页导入 JSON，批量选择视频文件，按文件名匹配。检查每个片段的“已就绪”状态。
4. 校验包括重复片段编号、负数或无效时间、起止时间/配置时长不一致、文件缺失、解码错误以及实际视频时长不匹配。时长容差为 0.25 秒。
5. 原视频起点无法仅从切分文件推断，需研究者根据切分记录核对；有非零 PTS 或转码偏移时，应重新校准起点和片段素材后再开展实验。

样例配置对应两段 16 秒视频。`tests/fixtures/V001_S01.mp4` 是带变化测试图案和时间文字的合成测试素材，可复制并重命名为 `V001_S02.mp4`，用于体验完整两片段流程。它不是正式传统节日实验素材。

## 阅读与独立练习阶段

新实验按“首页 → 操作说明（至少 30 秒）→ 练习视频 → 练习提交 → 主动开始正式实验”进行。
倒计时结束不自动跳转。练习复用正式工作区，至少保存一张已关联任务且理由完整的关键帧才能提交，不设置数量上限。

已配置独立练习视频 `public/practice/practice.mp4`，通过 `public/practice/config.json` 配置资源相对路径、标题和原视频起点。视频时长自动读取。也可在练习页面单独选择本地练习视频。不能用正式片段自动代替练习视频。详情见 [练习素材说明](public/practice/README.md)。

练习视频使用浏览器原生媒体请求按需读取，无需先完整下载整个文件。网络读取设有超时，失败后可“重试加载”或选择本地练习文件；本地选择会取消尚未完成的网络加载。

练习使用独立组件实例和内存 Session，不读取或写入正式会话、片段索引、完成进度及导出文件。提交练习后销毁其截图和理由，点击“开始正式实验”才初始化空白正式结果。参与者编号保持一致。
按参与者编号分别保存阅读确认与练习提交状态：阅读满 30 秒并主动确认后记为已阅读；成功提交练习后记为已练习。同一参与者后续开始或恢复时只补做尚未完成的步骤，两项均完成后可直接进入正式实验。即使尚未开始正式实验就刷新，已完成的步骤也会保留。
练习截图和理由仍仅保存在内存，刷新后丢弃；清除正式会话不清除流程完成状态。记录限于当前浏览器和站点，清除站点数据或换浏览器后需重新完成。
完成标记以参与者编号单独存于 IndexedDB 的 `onboarding-participant:` 命名空间，不改变正式数据结构或导出字段。旧版本的已阅读记录以及恢复旧会话时可验证的阅读练习完成记录会自动兼容。

## 参与者操作

1. 输入匿名编号（如 P01），阅读完整四任务说明并勾选确认，点击开始后阅读操作说明 30 秒，完成独立练习，再主动开始正式实验。
2. 自由播放、拖动、快进快退，或输入片段内秒数定位。点击“截取当前画面”暂停视频并截取真实 PNG。
3. 弹窗中选择一个或多个任务，为每项任务单独填写理由并保存；取消则不纳入结果。重复时间点可复用已有帧，也可仍然新增。
4. 右侧按 T1—T4 查看结果，图片可放大，支持理由编辑、任务调整、移出单项任务和整张删除。
5. 完成片段时核对各任务画面。0 张允许提交，需选择原因；选择“其他原因”需补充说明。填写片段完成说明后提交，按顺序进入下一片段。
6. 已提交片段可通过片段下拉列表回看。修改结果后需重新确认提交，导出使用最终结果。
7. 全部片段提交后进入“实验已完成”结束页，查看参与者编号、提交数量及保存状态，再预览并下载 ZIP，可重复导出。可返回检查结果；修改后需重新提交相应片段，全部提交后再次进入结束页。刷新恢复已完成的会话会回到结束页。打开 ZIP 检查完整后，明确确认才能清除本机会话并交给下一位参与者。

## 保存与恢复

已确认的帧、Blob、任务关联、理由、空结果、完成说明和当前片段均保存到 IndexedDB。每次结果修改、提交及片段切换立即排队保存，页面底部显示保存状态；失败会明确提示并提供重试。

刷新后不会创建新 session_id。恢复需输入原参与者编号；这是同机交接防误操作措施，不是身份认证。素材文件仅保存在页面内存，刷新后需要重新关联；原有图片和结果不受影响。未确认的截图编辑不属于已保存结果，刷新或关闭前会触发浏览器提醒。切换片段在弹窗关闭后才能操作。

下一位参与者开始前必须完成前一位会话导出和清除。清除只删除会话，材料配置保留。应用不自动清除记录，也不保存修改历史。

## 时间精度

`absolute_time_sec = start_time_sec + relative_time_sec`，数值以秒保存、保留三位小数，界面显示 `HH:MM:SS.mmm`。支持时优先读取 `requestVideoFrameCallback` 的已显示帧时间，否则使用 `currentTime`。截帧同步复制 Canvas 后才异步编码 PNG，避免编码期间时间变化。

逐帧按钮按用户选择的 24/25/30/60 fps 步长近似 seek，不能保证任意可变帧率素材的严格逐帧定位。毫秒数值精度不代表解码/定位具有毫秒级准确度。正式实验请先用目标浏览器和真实素材做预实验。
